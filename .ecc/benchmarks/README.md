# Launch benchmarks

These credential-free JSON baselines are shared source artifacts. Full browser traces, screenshots and transient logs stay in ignored `output/launch-20261016/` or the browser tool's temporary storage. Baselines do not contain account identifiers, Telegram launch signatures, private URLs or credentials.

Build the backend and all three frontends first. Run `node scripts/benchmark-browser.cjs baseline` with `PAIRTALK_PLAYWRIGHT_MODULE` pointing to an installed Playwright module and optionally `PAIRTALK_CHROME_PATH` pointing to Chrome. The configured Codex workspace runtime provides Playwright without changing app dependencies. Use `after` for subsequent comparison. `BENCH_RUNS` accepts 3–10 and defaults to five fresh browser contexts per surface.

The browser harness serves actual production assets with gzip and synthetic API/Telegram responses on ephemeral loopback ports. It delays response headers by 150ms and paces compressed bytes at a nominal 200,000 bytes/s using a shared timer; Windows scheduling can lower the effective rate. It applies 4× CPU slowdown at 390×844. Cache is disabled. A control request must verify the header delay. This is a delivery model, not a calibrated mobile network. Initial resource weight is measured before interactions; call/media chunks loaded later do not count as initial JS. Observed event duration is a lab interaction sample, not field INP. Total TTFB is measured from navigation start; request-to-response time is reported separately. Rejected initial-method and CPU-only experiments stay in ignored local output: Chrome accepted CDP network throttling but a control request proved it ineffective. Only the verified schema-version-two delivery-model baseline is shared here.

The baseline authentication fixture omitted `hasActiveCall`; the actual backend already returned it. Both led the original UI to make an extra lookup. The after fixture includes the real `false` value to exercise the corrected normal startup path. This removes a request rather than changing backend work or bypassing authentication. Public compiled CSS now travels inside HTML: cold navigation avoids a blocking request, while repeat navigation must transfer those style bytes with HTML again. Fingerprinted external and lazy assets receive immutable cache headers separately.

For API benchmarks, start the repository's owned PostgreSQL verification database on 127.0.0.1:55432 and the Lua-compatible verification Redis on 127.0.0.1:56379. Run `node scripts/benchmark-api.cjs baseline <private-runtime-json-path>`; use `after` for comparison. The guard refuses hosted databases. It runs actual authentication, route and Prisma code with synthetic signed accounts, normal enabled rate limits and persistent fixtures, then removes only its rows/keys. Each route has 100-request serial and 10-concurrency cases. Ten accounts share each case; the benchmark does not bypass per-user limits. It neither starts bot polling nor calls payment/media providers.

Local measurements do not prove Railway capacity, real Redis performance, Telegram/WebView device latency, LiveKit limits or concurrent voice quality. Live browser/API observations must be labeled separately with host, profile, cache state and sample size. Build timings must state cache state, and unsupported Docker/Linux checks must remain explicit gaps.
